# 01. 원래 구조 (2023)

리워크를 시작할 때(커밋 `1ce65d5`)의 프로젝트 상태를 정리합니다.
이 문서를 읽으면 원본의 엔진 구조와 구현 범위, 그리고 리워크에서 고칠 문제 목록을 알 수 있습니다.
분석은 서브에이전트 3개가 나눠 맡았고, 핵심 주장은 오케스트레이터가 코드에서 다시 확인했습니다. 진행 방식은 [03. AI 개발 실험 기록](03-ai-experiment.md)에 있습니다.

## 규모

| 항목 | 값 |
|---|---|

| 커밋 | 100개 (2023년 3월 44, 4월 45, 5월 10, 8월 1) |

## 엔진 구조

강의용 엔진(`ya` 접두사)을 바탕으로 직접 확장한 구조입니다.

```
Application  메인 루프: Update → Render → Destroy(지연 삭제)
 ├─ Time            QueryPerformanceCounter로 프레임 시간 계산 (상한·고정값 없음)
 ├─ Input           A~Z, 방향키, 마우스 좌우 버튼만 지원
 ├─ Camera          플레이어 추적, 좌·상 경계와 하드코딩된 우측 경계 3350
 ├─ CollisionManager AABB 충돌, 16x16 레이어 충돌 행렬, Enter/Stay/Exit 콜백
 ├─ SoundManager    DirectSound, WAV만 지원
 └─ SceneManager → Scene → Layer(13종) → GameObject → Component
                                                      (Transform, Animator, Collider, Rigidbody)
```

| 구성 요소 | 특징 |
|---|---|
| 렌더링 | BMP만 읽고, 마젠타(255,0,255)를 투명색으로 씁니다(`TransparentBlt`). 좌우 반전이 없어서 왼쪽·오른쪽 이미지를 따로 둡니다 |
| 애니메이션 | 스프라이트 시트를 균등 분할하거나, 폴더의 프레임 BMP를 실행 중에 한 장으로 합칩니다 |
| 물리 | 중력 800, 착지 플래그가 켜지면 수직 속도를 제거합니다. 착지 판정은 Ground·Platform의 충돌 콜백이 담당합니다 |
| 지형 | 보이는 타일과 실제 충돌하는 지형(보이지 않는 Ground 박스, Platform 박스)이 분리돼 있습니다 |
| 타일 툴 | 별도 아틀라스 창에서 타일을 골라 배치하고 파일로 저장·로드합니다 |

## 씬 흐름

```
Tool(시작) ─N→ Title ─N→ Stage1 ─게이트 F 또는 N→ Stage2 ─게이트 F 또는 N→ Boss (이후 흐름 없음)
```

- 시작 씬이 타일 편집 툴이었습니다.
- 모든 씬에 N키로 다음 씬으로 넘어가는 개발용 키가 남아 있습니다.
- 각 씬은 시작할 때 한 번만 초기화되므로 다시 들어가거나 재시작할 수 없습니다.

## 구현 범위

| 영역 | 구현됨 | 미구현 |
|---|---|---|
| 플레이어 | 이동, 대시, 2타 콤보, 점프 공격, 머리 던지기(A), 머리로 순간이동(S), 발판 아래로 내려가기 | HP, 피격, 사망, 스컬 교대 |
| 몬스터 | Ent 1종: 무작위 배회, 피격 경직, HP 5 | 추적, 공격(함수가 비어 있음), 사망 연출 |
| 보스 | 부위별 FSM, 패턴 3종(펀치, 쓸기, 8방향 탄), HP 30 | 플레이어에게 주는 피해, 사망 이후 흐름 |
| 오브젝트 | 아이템 게이트, 보스 게이트(몬스터 전멸 시 활성) | 아이템 보상, 스컬 게이트 배치 |
| UI | — | HUD, 체력바, 결과 화면, 엔딩 |

## 알려진 문제

리워크에서 다룰 문제입니다. "확인 방법"이 **측정**이면 [테스트 하네스](02-changes.md#1-테스트-하네스)로 수치를 직접 재현한 것이고, **코드**면 소스에서 확인한 것입니다.

| 문제 | 원인 | 확인 방법 | 처리 단계 |
|---|---|---|---|
| 시작 씬이 타일 툴 | `SceneManager::Initialize`가 Tool을 활성화 | 코드 | Phase 0 (해결) |
| 마우스가 창 밖이면 스테이지 타일이 사라짐 | 툴 클릭용 마우스 범위 검사가 타일 생성 함수 안에 있어서, 스테이지 로드에도 적용됨 | 코드, 측정 | Phase 0 (해결) |
| 소스 인코딩 혼재 | 파일마다 CP949·UTF-8·ASCII가 섞여 있음 | 코드 | Phase 0 (해결) |
| 낙하 속도 상한이 적용되지 않음 | 속도 제한 값을 계산만 하고 속도에 다시 넣지 않음 | 측정: 상한 1000인데 1440까지 올라감 | Phase 1 (해결) |
| 착지 순간 지면 아래로 8px 파고듦 | 콜라이더가 Rigidbody보다 먼저 갱신돼 한 프레임 늦음 | 측정: 지면 1726인데 1734까지 내려감 | Phase 1 (해결) |
| 마찰 임시 수정 | 2023-08 커밋이 증상만 막음. 마찰이 수직 속도에도 걸림 | 코드 | Phase 1 (해결) |
| 업데이트 중 오브젝트 생성 시 정의되지 않은 동작 | 범위 기반 for 문 도중에 벡터에 추가 | 코드 | Phase 1 (해결) |
| Pause·Death 상태 오브젝트도 충돌 | 충돌 검사에서 상태를 확인하지 않음 | 측정: 멈춘 머리가 몬스터를 계속 때려 268프레임에 1마리 사망 | Phase 1 (해결) |
| 애니메이션 프레임 순서가 뒤섞임 | 파일 이름이 0으로 채워져 있지 않아 `_10`이 `_2`보다 먼저 로드됨 | 측정: 보스 탄 Loop가 0, 1, 10~19, 2~9 순서로 재생됨(스크린샷 비교) | Phase 1 (해결) |
| 없는 애니메이션을 재생하면 크래시 | null 포인터 역참조 | 코드 | Phase 1 (해결) |
| 완료 이벤트가 매 프레임 반복 호출 | 애니메이션이 끝난 뒤에도 완료 상태를 계속 보고 | 측정: 보스 손 PutOn 이벤트가 15초에 626번 | Phase 1 (해결) |
| 이미지 GDI 핸들 누수 | 이미지 소멸자가 DC와 비트맵을 해제하지 않음 | 코드 | Phase 1 (해결) |
| VS 2026에서 빌드 실패 (`MSB8020`) | 프로젝트가 VS2022 툴셋(v143)을 고정 지정 | 원작자가 발견 | Phase 1 (해결) |
| Release·x86 구성 빌드 실패 | C++ 표준이 C++14로 남아 있어 `std::filesystem` 사용 불가 | 빌드 | 미정 |
| 공중에서 순간이동하면 몸이 떠 있음 | 스컬 교대 시 착지 상태를 그대로 복사 | 시나리오 | Phase 2 |
| 사운드 하나가 재생되지 않음 | `Skul_Reborn_Rise`를 다른 사운드와 같은 키로 로드 | 코드 | Phase 2 |
| 낙하 상태에서 공격 코드까지 실행 | `switch`에 `break` 누락 (`yaSkul.cpp` Fall) | 코드 | Phase 2 |
| 플레이어·보스 공격 판정 미완성 | 플레이어 충돌 콜백이 비어 있고, 보스 손·탄에 피해 처리가 없음 | 코드 | Phase 2 |
| UI 없음 | UI 레이어는 정의만 있고 사용하지 않음 | 코드 | Phase 3 |
